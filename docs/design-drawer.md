# JARVIS · 情景抽屉（Scenario Drawer）设计方案

> 效果图：`_mockup/drawer-mockup.html`

---

## 一、设计目标

中央星图（Cortex 双层脑）不动。两侧面板从"平铺列表"升级为**情景抽屉**——列表里的每一条数据都是入口，点击后从对应侧边滑出一个抽屉，展示该条目的详情、图表和 3D 交互效果。

**核心交互**：
```
侧边栏列表项 ──点击──▶ 抽屉滑出（覆盖星图区域）──展开详情/图表/3D──
                                                              └─ ✕ 或点外部 ──▶ 抽屉收起，列表恢复
```

## 二、与现有 UI 的关系

### 保留不动

| 区域 | 说明 |
|---|---|
| 顶栏 | 品牌 / 状态 / KPIs / 健康灯 |
| 中央星图 | WebGL2 双层脑 Cortex，不动 |
| 中央聊天区 | SSE 对话 + 工具调用 + 语音，不动 |
| 底部输入栏 | 语音 + 文字输入，不动 |

### 升级重构

| 现有面板 | 升级为 | 理由 |
|---|---|---|
| 左栏 6 个面板（平铺） | **6 个抽屉入口** | 每个面板内容量不一，平铺挤压视线；抽屉按需展开 |
| 右栏 5 个面板（平铺） | **5 个抽屉入口** | 同上 |
| memcard 浮动详情卡 | **升级为完整抽屉** | memcard 只有 286px 宽，信息密度低；抽屉有 ~400px，可容纳图表和 3D |

## 四、抽屉设计

### 4.1 基本规格

| 属性 | 值 | 说明 |
|---|---|---|
| 宽度 | 400px | 足够容纳图表 + 3D 视口 + 文字说明 |
| 高度 | 100% 可用区（顶栏到底部栏之间） | 上下无留白，沉浸式 |
| 滑入方向 | 左栏→从左滑出；右栏→从右滑出 | 对应关系明确 |
| 动画 | `transform:translateX(±100%) → translateX(0)` | 300ms cubic-bezier(.4,0,.2,1) |
| 背景 | `rgba(11,17,26,.97)` + `backdrop-filter:blur(20px)` | 几乎全黑，与星图形成对比 |
| 遮罩 | 星图区域有半透明遮罩（不阻塞星图旋转） | 抽屉外的星图仍可看到旋转动画 |
| 关闭 | ✕ 按钮 / 点遮罩区域 / Esc | 三种方式，符合直觉 |
| 内容滚动 | 内部独立滚动，不影响主界面 | 抽屉有独立的滚动上下文 |

### 4.2 抽屉结构（通用）

```
┌─────────────────────────────────┐
│ [分类标签]  [标题]              [✕] │  ← 抽屉头 48px
├─────────────────────────────────┤
│                                 │
│  ┌─ 核心指标卡 ─────────────┐   │
│  │  数值1   数值2   数值3   │   │  ← 顶部 KPI 行
│  └─────────────────────────┘   │
│                                 │
│  ┌─ 详情区（文字/表格/标签）──┐   │
│  │                           │   │  ← 文本说明 + 结构数据
│  │                           │   │
│  └─────────────────────────┘   │
│                                 │
```

## 五、3D 效果方案

### 5.1 技术路线

零依赖，全部 Canvas2D + CSS 3D Transform 模拟（不新增 WebGL2 上下文——星图已占用一个 WebGL2 context，浏览器对 WebGL context 数量有限制）。

| 3D 效果 | 实现方式 | 复杂度 |
|---|---|---|
| 3D K线柱阵 | Canvas2D 投影（X/Y/Z → X'/Y'） | 中 |
| 3D 记忆球 | Canvas2D 球面投影 + 连线 | 中 |
| 3D 雷达 | Canvas2D 3D雷达（多边形+连线） | 低 |
| 3D 时间轴 | CSS 3D `transform:perspective+rotateX` | 低 |
| 3D 健康球 | Canvas2D 球面 + 热力着色 | 低 |

### 5.2 与现有星图的关系

- 星图使用 WebGL2 context（`starfield.js`）
- 抽屉 3D 使用 Canvas2D 伪 3D（避免 WebGL context 超限）
- 如果未来确需 WebGL2 抽屉，可以复用星图的 GL context（`gl.getContextAttributes()` 检查）
- 抽屉 3D 的 `starfield` 聚焦模式可以直接通过 SSE 通知主星图（`window.STAR.focusOn(nodeId)`）

## 八、与现有 memcard 的关系

现有 `memcard`（286px 浮动卡）是记忆星图点击后的详情弹窗。情景抽屉上线后：

1. `memcard` 保留：星图节点点击 → 快速弹出小卡（286px），保持现有快速查看体验
2. 小卡上增加"展开详情 →"按钮 → 打开完整抽屉（400px），展示图表+3D
3. 抽屉关闭后回到星图，焦点回到之前点击的节点

这样 memcard 是"快速预览"，抽屉是"深度查看"，两个层级不冲突。

## 十、约束

| 约束 | 应对 |
|---|---|
| 只允许 better-sqlite3 | 抽屉内容纯前端渲染，不引图表库 |
| 星图已占 WebGL2 context | 抽屉 3D 用 Canvas2D 伪 3D，不新增 WebGL2 |
| 抽屉不能阻塞星图旋转 | 遮罩只覆盖星图中央区域，抽屉外侧星图仍可见动画 |
| 抽屉内容不应太复杂 | 抽屉宽 400px，内容紧凑，大图表给"展开到对话"按钮 |
| 侧边栏列表过长 | 每个面板最多显示 6 条，超出滚动（保持 .pb 滚动行为不变） |
